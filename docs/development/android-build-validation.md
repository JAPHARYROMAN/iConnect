# Android CI download recovery

The [96a5206 run](https://github.com/JAPHARYROMAN/iConnect/actions/runs/42579053992) fails before compilation because the Gradle 8.13 distribution returns HTTP 504. The [3551845 run](https://github.com/JAPHARYROMAN/iConnect/actions/runs/42581368152) gets past wrapper setup, then fails resolving Kotlin compiler 2.3.0: its dependency error names the Maven Central artifact and reports HTTP 504 from the GitHub release URL. These failures do not establish a compiler, test or application defect. The same Android application previously passed its local debug, instrumentation, unsigned Release, 87 JVM and lint checks.

[The CI launcher](../../tools/build_android_ci.py) now permits at most three attempts when every reported Gradle failure is an identified transient artifact download. It retains the existing wrapper, version/checksum settings, repositories and all five requested build/test/lint tasks. It adds plain console output, saves each attempt separately and applies a short bounded delay. It does not switch mirrors or modify build inputs.

Compiler errors, failing tests, lint findings, checksum/signature/certificate failures, memory failures, unrelated task failures and ambiguous or oversized output end the invocation. A failed final attempt remains a failing job. The workflow uses the repository's existing pinned Python setup action and runs the launcher tests independently of the Android job.

Ten tests pass with ResourceWarnings treated as errors, including real child-process controls for one transient failure followed by success, immediate return of a failed test, three exhausted download attempts and preservation of all attempt logs. Parser cases include wrapper bootstrap, Kotlin classpath resolution, multiple simultaneous failures and integrity refusals. The Linux and Windows commands retain all five original tasks. Captured full CI logs separately confirm that both observed download failures qualify and the native Windows handshake failure does not.

The [hosted Android job at `6bef23a`](https://github.com/JAPHARYROMAN/iConnect/actions/runs/42586362016/job/129057046010) succeeds on its first attempt in 8 minutes 40 seconds. All five build/test/lint tasks complete. This establishes successful hosted execution of the launcher; retry behavior is covered by the controlled failures above, since this hosted job did not need a retry. The [completed workflow](https://github.com/JAPHARYROMAN/iConnect/actions/runs/42586362016) succeeds in all four jobs: Windows, Windows large files, Android and native notice/tool controls. These results do not close device, interoperability, physical-network, independent review or release gates.

The later [315d8bb workflow](https://github.com/JAPHARYROMAN/iConnect/actions/runs/42592895596) also succeeds in all four jobs, including the new captured-baseline verifier controls. This result covers the provider-refusal preflight checkpoint; the sender-control lifecycle correction has its own local build/device/native evidence.
