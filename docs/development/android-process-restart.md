# Android process-death checkpoint probe

Prepared 7 November 2026. The instrumentation APK builds successfully, and its packaged manifest contains the probe alongside the normal JUnit runner. PowerShell parsing passes. The driver correctly refuses both a mismatched AVD and an already-running app on the owned emulator. Actual process-death execution is pending; this probe does not yet establish a passing recovery result. The production APK SHA-256 is unchanged by this test-only addition.

The existing manager-reopen tests leave the application process alive. This opt-in test instead transfers generated bytes through `AndroidDownloadManager`, waits with a durable 1,048,576-byte checkpoint and a 32,768-byte uncommitted private tail, and lets an external driver force-stop the actual app process. A second instrumentation invocation must have a different process ID, reacquire the native queue lock, load an inactive interrupted receipt and retain the original source ticket. It resumes explicitly from the saved checkpoint without preparing another ticket, saves through the test DocumentsProvider, and verifies the complete 2,097,169-byte SHA-256 and exactly one published copy.

`ProcessRestartProbe` is a separate instrumentation entry in the test APK. Ordinary JUnit discovery does not run it. The seed phase waits for external process termination and has a five-minute fallback deadline; that fallback is a failed probe, not proof of abrupt termination. No manager shutdown, pause or coroutine cleanup runs when Android force-stops the seed process.

## Running on a disposable emulator

Build and install the debug app and test APK. Finish any existing instrumentation first. Stop the idle test app on the explicitly owned disposable emulator, then run:

```powershell
./tools/test-android-process-restart.ps1 -Serial emulator-5568 -ExpectedAvdName iconnect-large-files
```

The driver requires an emulator serial and an exact AVD name. It refuses a mismatched AVD or an already-running test app. Before terminating anything, it checks the active seed process ID against the synced checkpoint marker and rechecks the AVD identity. It never clears application data or uninstalls packages. The resume result must bind the original/new process IDs, run token, checkpoint, private length, resumed offset, original source receipt and final hash. ADB's exit status alone does not establish success.

Logs and a JSON report are written under the repository's ignored `.tools/android-process-restart/<random-run>/` directory. Successful execution removes its generated provider fixture and receiving record through their normal APIs. Small private probe metadata remains for inspection. Failed probes preserve available state and copies for diagnosis; the driver does not remove files or stop an unrelated process on failure.

This is an application-process kill on an owned emulator. It is not a device reboot or power-loss test, a document-provider process kill, an encrypted peer session, a batch crash matrix, a physical-device result or proof for every publication crash point. The source is generated and supplied by an in-process protocol fixture. Provider publication and persisted Android URI permissions use the actual Android APIs.
