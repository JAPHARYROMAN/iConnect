# Android send and local-copy payload estimates

Android ordinary private uploads, standalone offline copies and current local-batch files now show recent payload rates and approximate remaining-payload time. The native cards distinguish source/receipt checks, payload copying, receiver verification, private verification and provider saving. A completed payload is not presented as a completed provider or receiver copy.

## Observation boundaries

An upload starts observations only after checking its retained private source and validating its receiver receipt. That receipt establishes the starting offset; earlier accepted bytes and source-checking time do not count as new sending. Each validated range acknowledgement updates a memory-only stream. Lost replies and invalid offsets cannot advance it, and every exit clears it. Resume has a fresh run identity even when a collector misses an intermediate stopped state. The view also scopes observations to the current connection and configured peer payload limit.

Offline copies use their private receiver's existing validated range progress, with a fresh identity per receiving attempt. Live copied bytes are shown separately from the durable resume checkpoint. Standalone and batch stores have independent trackers and no peer network limit. Their existing foreground withdrawal, source leases, checkpointing, SHA-256, collision decisions and provider read-back remain unchanged. Hiding or closing clears display measurements and preserves the original pause behavior. A restarted store begins with empty display measurements. Provider internet use remains independent of iConnect's peer payload controls.

The existing bounded tracker requires two seconds of progress, uses a recent 20-second window, stops showing a rate after ten seconds without progress and resets on changed scope, rollback or pause. Periodic refreshes update view state without making file requests. Only active matching rows and observations contribute; stale source, peer, ticket, version, size or receiver descriptors are ignored. Publication of a durable row just before its live-flow update does not erase otherwise valid samples. Samples cannot advance checkpoints, change folder grants, authorize background work or resume a job. Rates and run identities are not persisted, exported or sent to the coordinator.
