# Android connection observations and callback isolation

This phase extends [Windows connection observations](phase-54-windows-change-and-connection-observations.md) to the phone's existing coordinator and native-session paths. It does not add remote access, automatic retries or a wire capability.

## Observe coordination separately from authenticated access

Android now records separate compiled coordinator and direct-connection actions. A coordinator attempt is requested before the socket handshake; its existing validated registration notice can complete that coordinator connection. This does not complete a direct device connection or authorize files. Coordinator observations have no peer fingerprint. Transport, protocol, availability-reporting and timeout failures use explicit failed causes, rather than interpreting display/error strings.

Owner disconnect/cancel, foreground/network withdrawal, context refresh, remote closure and unavailable-peer handling pass explicit typed causes through the existing cancellation barriers. A generation change ignores later socket callbacks from the canceled attempt. Local pause remains distinct from owner cancellation. Selected notification-backed transfer authority and ordinary foreground storage limits retain their existing checks.

The native session emits a requested direct attempt and records completion only after the existing signature, pinned identity, DTLS/direct-path and mutual-readiness checks succeed. It records the pinned peer fingerprint, never session IDs, SDP, candidate addresses, configured endpoints, public-key bytes or error text. A directly observed channel close after readiness can report ended; ICE/protocol/authentication failures remain failed. Superseded attempts end separately, and unavailable peers are refused. The earlier general connection kind remains readable in existing histories.

## Keep observation outside authority

Native history, display-log and authentication-status callbacks are individually contained. Callback exceptions cannot turn an authenticated file request into a transport failure or prevent the normal close path. The native authenticated/closed flags remain independent authority checks. A terminal close has a single atomic gate, so repeated close calls and queued callbacks cannot append a second terminal observation or dispose native objects again. Reentrant close during a completion observation prevents a later stale authenticated UI notification.

A fixed open-channel diagnostic describes negotiation before device authentication. It does not claim readiness. Identity/challenge rejection has a fixed diagnostic suitable for verifying the negative boundary. Neither diagnostic text is passed into activity. The existing bounded 64-command history writer, off/retention/clear controls, dropped-event reporting and diagnostic-export exclusions continue to apply. Observations can be missing after storage failure, overload or process death; they are not permission or forensic authority. A terminal connection observation does not prove file/checkpoint publication or every OS cleanup effect.

## Verification and remaining gates

Debug, instrumentation and unsigned release builds pass in **2 minutes 30 seconds**, with **39 JVM tests**, zero failures/errors, and lint with **zero errors and 67 existing warnings**. The first focused native run passes **23 cases in 18.571 seconds**, covering both actual native initiator roles, bounded requests despite throwing history/log/status observers, an opened channel presenting an unpinned identity, repeated/pre-ready owner close, real refused socket attempts, off/reopen, owner cancellation and foreground withdrawal without a stale callback outcome. Existing activity/control/reconnect cases also pass. Evidence: `.tools/phase55-android-build.log`, generated JVM/lint reports and `.tools/phase55-android-focused.log`.

The final test-only rebuild passes in **33 seconds**, with application bytes unchanged. The final focused native run passes **24 cases in 15.169 seconds**, including five new cases. At real cryptographic readiness, an activity observer deliberately closes the session and throws; the session remains closed, emits one terminal cancellation, and never publishes a stale authenticated UI status. The other new cases verify identity/challenge rejection after an actual channel open, denial of requests on the closed channel, persisted fixed-data failure records, repeated/pre-ready close, refused coordinator attempts, recording off/reopen, queued owner cancellation and foreground withdrawal. Existing native request, storage/history/control and reconnect checks also pass. Evidence: `.tools/phase55-android-verified-build.log`, `.tools/phase55-gradle-final-stop.log` and `.tools/phase55-android-final-focused.log`.

The complete selected native regression passes **347 device cases in 748.125 seconds**, including the five new cases and existing transfer, recovery, native UI, diagnostics, history, preview, protocol and lifecycle checks. It retains the same four coordinator-dependent interoperability-class exclusions and four separately recorded full-capacity exclusions as phase 53. This is not capacity-performance, actual power/process-loss, physical-device or fresh encrypted Windows–Android evidence. The runner finishes with `OK (347 tests)`. Evidence: `.tools/phase55-android-regression.log`.

Tests use the existing real native-peer fixtures and refused loopback socket pattern. They do not start a coordinator or replace the pending encrypted Windows–Android/physical-network verification.

A follow-up lifecycle audit identified fresh signed candidates/answers arriving after a direct attempt ends. The phase-55 Windows handler forwarded a matching candidate to its retained session without an explicit closed-session check. Android ignored signals for a retained closed session, but its unavailable-peer path removed that session without adding the ID to the discarded set. [Phase 56](phase-56-ended-session-signaling.md) records the dedicated reproduction, correction and verification of that boundary; the earlier readiness and superseded-offer cases alone did not prove it.

Windows source was not changed in this phase; [phase 54](phase-54-windows-change-and-connection-observations.md) remains its latest verification. Broader pairing/authentication/control failures, process/power loss, notification/device/provider/OS matrices, sustained overload, history-backup management, supported upgrade/downgrade and independent security/privacy review remain open. Older development binaries may not recognize the new enum strings and must preserve unsupported journals. Windows GUI automation remains stopped after the user's Escape. Batch advertisement, encrypted interoperability, physical-network, signing and packaging gates remain in the [completion audit](completion.md). The [operator kit](physical-network-validation.md) adds step 29 and result fields; it is prepared for execution after implementation, as requested, and was not executed in this phase.
